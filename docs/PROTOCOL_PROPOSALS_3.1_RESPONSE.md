## P1. Contract vectors

`crates/msst-ipc-protocol/tests/vectors/*.json` — generated by Core's real
IPC handler from a fixed fixture (`src/contract_tests.rs`):

- one file per local query: `{"request": <frame>, "response": <frame>}`
  (`health`, `get_system_state`, `get_nodes`, `get_node`, `get_acl_rules`,
  `get_acl_groups`, `get_access_log`, `get_pending_auth`, `get_net_settings`,
  `get_endpoints`, `get_traffic_stats`, `get_path_view`, `get_connections`,
  `get_contacts`, `get_services`, `get_logs`, plus error examples);
- `events.json`: an array of event frames (`room_state_changed`,
  `identity_changed`, `settings_changed`, `node_state_changed`).

Volatile values are normalized: `generation`, `timestamp_ms`,
`last_outbound_unix`, `reported_at` → `0`; `expires_in_secs` → `60`;
`request_id` → `"<request_id>"`.  Coordinator proxies (`GetRelays`, DNS,
rooms, auth) are not included — their bodies are the coordinator's.

Core's test fails when a handler's output differs from the files;
regenerate with `UPDATE_VECTORS=1 cargo test -p msst-net-core contract`.
`crates/msst-ipc-protocol/tests/vectors.rs` checks that every file decodes
with the protocol types — the Controller can run the same check against its
own payload decoders.

## P2. Events

Now emitted:

| Event | When |
|-------|------|
| `NodeAdded` | a peer becomes known (room, fetch, cache restore) |
| `NodeStateChanged` | a known peer's data changed (`change` = its full current record: ipv4/ipv6, hostname, names, handles, user_id, preferred_relay, is_authenticated) |
| `NodeRemoved` | a peer is evicted (no room / rule / communication reason left) |
| `RoomStateChanged` | room_state, member joined, member left, room left. Same content as `GetSystemState`'s room view: `room_id`/`room_name` (`null` when not in a room), `relay`, `peers` with `device_id`, `ipv4`, `ipv6`, `hostname`, `display_name` (own device included) |
| `AccessRequestResolved` *(0.3)* | `{request_id, decision, rule_id}` after `AuthDecision` |
| `IdentityChanged` *(0.3)* | display name / handle / hostname / assigned IPv4 / authentication changed; full new values, `null` = unset |
| `SettingsChanged` *(0.3)* | `scope: "net"` (settings as `GetNetSettings`) or `"ping"` (`{"ping_enabled"}`) |

Room membership changes use `RoomStateChanged` (full state) rather than
separate join/leave events.

## P3. `ClearAclRules`

Deletes every rule atomically (persisted once).  Response
`{"deleted": <count>}`; one `AclChanged {action: "deleted"}` per rule.

## P4. `generation`

Advanced whenever Controller-visible state changes: identity, rules,
groups, settings, rooms and room members, known nodes, paths, relay,
endpoints, pending authorization requests.  Not advanced by high-rate
diagnostics (traffic counters, contact timestamps, logs, access log).
Read it before and after a multi-query rebuild; if it changed, query
again.  It restarts from 0 when Core restarts.

## P5. Event sequence numbers

Deferred.  Resyncing all resources on reconnect plus P4 covers the
recovery case; seq/replay can target a later minor version if needed.

## P6. Rule updates

`UpdateAclRule` keeps the 3.0.x fields (`enabled`, `comment`,
`expires_at`).  Any other field is rejected with `invalid_patch` (same for
`UpdateAclGroup`: only `name`, `member_ids`).  Full replacement is not
implemented — "copy as new rule" remains the way to change sources/ports.

## P7. Network settings validation

`mtu_override`: `null` or an integer in **1280–1500** (IPv6 minimum to
Ethernet MTU).  `keepalive_secs`: `null` or a positive integer (clamped to
5–30, as 3.0.x); since 3.1.7 it sets the relay keepalive only — the
direct-path liveness ping stays at 1 s (3.0.x applied it to both, so any
value set slowed dead-direct-path detection from 5 s to up to a minute).  `preferred_relay`: `null` or a string.  Anything else →
`invalid_settings`, nothing changed.

## P8. Socket protection (embedded Core)

`EmbeddedCore::start(data_dir, ipc_socket, coordinator_url, protect)` —
`protect: Option<Arc<dyn Fn(RawFd) -> bool + Send + Sync>>`, i.e.
`VpnService.protect(fd)`.  It is installed once per process and called for
every socket Core opens, before use:

| Socket | How |
|--------|-----|
| UDP data plane, relay probes, DNS upstream, diagnostic ping, IPv6 probe | created via `netsock`, protected |
| Coordinator WebSocket | TCP connected and protected by Core, then TLS + WS handshake on it |
| Coordinator HTTP (`reqwest`) | through an in-process SOCKS5 proxy on 127.0.0.1 (`socks5h`, proxy-side DNS) whose upstream connections are protected; random per-process username/password so other apps can't use it to bypass the VPN |

If `protect` returns `false` the socket is not created (the operation
fails) rather than leaking traffic into the VPN.  The callback must be
thread-safe and must not call back into Core.  JNI glue: pass a closure
that calls `VpnService.protect(int)` on the service instance (attach the
calling thread to the JVM).  Desktop is unchanged (no callback, no proxy).

Verified on Linux with a recording callback (every UDP/TCP socket and every
proxy upstream connection protected, failing callback fails the socket,
proxy refuses missing/wrong credentials); lockdown mode itself needs an
Android device.

## P9. `Health`

- `tun_ready` is `true` only while a TUN is attached (relay-only mode →
  `false`).
- Unset `device_handle`, `user_handle`, `device_display_name`,
  `user_display_name`, `device_hostname` are `null` (also the own-device
  entry in room views).

## P10. Startup auth state

`Health.access_auth_required: bool` — set when Core finds no valid
credentials at startup or the coordinator answers 401 and refresh fails;
cleared after a successful OIDC login or token refresh.  The
`AccessAuthRequired` event is still sent, but the flag is the source of
truth for a Controller that connects later.

## P11. IPC bind failure

The IPC socket / pipe is bound before any task starts.  Failure aborts
startup: the daemon exits non-zero, `EmbeddedCore::start` returns an error.

## P12. Error codes

`msst_ipc_protocol::errors` lists every code with its meaning
(`errors::ALL`).  A Core test fails if a handler uses an undocumented code.
`message` stays diagnostic text — map codes to user messages, show
`message` only as detail.

## Follow-up (Controller feedback on 0.3)

- `UpdateDisplayName` / `UpdateHandle` replies: unset fields are now `null`
  (as in `Health` / `IdentityChanged`).
- The own device's IPv6 in room views (`GetSystemState`, `RoomStateChanged`)
  and `EmbeddedCore::virtual_ips` is canonical (`fd22:2222:2222:2222::1`).
  The coordinator `register` message keeps the 3.0.x derived text
  (`…::0000:0001`) for compatibility.

## Observed: stale binary

Rebuild Core: the protocol version is now 0.3.0.

## What the Controller should change

1. Treat protocol ≥ 0.3 as supporting `ClearAclRules` and the three new
   events; keep the 0.2 fallbacks for older Cores.
2. Read `Health.access_auth_required`; expect `null` for unset strings.
3. Handle `invalid_patch` / `invalid_settings` as validation errors.
4. Decode the contract vectors in Controller tests.
